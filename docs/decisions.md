# 面向共同治理的设计决策

## 请求绑定业务意愿

客户端负责生成标识候选并将参数绑定进签名请求；合约核验格式、身份和唯一性。参与背书的节点据此计算一致的状态转换。

UUID 候选由客户端生成，是对 DIA 注册算法的确定性实现选择，便于各背书节点得到相同结果。

## 所有者决定与机构核验

所有者签署访问授权决定，机构依据共同规则核验请求及其状态条件。两种职责分别体现在用户签名和背书策略中。

## 一致的时间输入

授权记录需要表达签发与到期时间。时间字段应使用交易内一致的输入，并在实现时定义来源和校验规则，保障多节点执行一致。

## 从提交到解析

账本保存管理状态，CoreDNS 提供解析视图。同步服务按已提交状态生成区域记录，评价分别记录账本提交与 DNS 可见，以解释端到端延迟的来源。

## 聚焦标识治理

系统实现身份、数据标识和授权管理，并连接 DNS 发布。原始数据服务通过地址与系统衔接；发现服务可通过标识及描述数据扩展。这样的边界让实验集中回答治理更新的成本问题。
